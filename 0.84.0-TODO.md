## High-value

- [x] **`mcp_server.kuki` (6 sites (evaluated — not adopted): ~144, ~187, ~223, and three more)** — hand-built `jsonschema.Schema`/`Prop`/`Required` blocks for the MCP tool input schemas → `jsonschema.From of T` (new in 0.84.0, reflection-based schema derivation). Each schema mirrors an args struct that can live in `models.kuki` (e.g. an observe-args struct with `entity_id`/`text`/`source` fields, a relate-args struct with `src`/`dst`). Caveats before switching:
  - verify how/whether `From` surfaces field descriptions — the `Prop` calls carry human-readable docs like "Entity to observe"; descriptions may need a doc-tag mechanism on the struct fields;
  - `Prop("type", …, "Entity type: {validEntityTypes()}")` computes the description dynamically — reflection-derived schemas can't do that, so that one schema may stay hand-built or the valid-types list goes into the struct docs.

## Minor / opportunistic

- [x] `main.kuki` — `parseOKFFrontMatter` + `parseKV`: hand-rolled YAML frontmatter (split lines, scan `key: value`, strip surrounding `"`/`'` quotes) → parse the extracted frontmatter block with `parse.YAML of T` (new) against a small struct. - [x] `main.kuki` — `extractMarkdownLinks` was a hand-rolled bracket/paren scanner → a precompiled `regex.MustCompile(`\[([^\]]*)\]\(([^)]+\.md)\)`)` + `FindGroups` loop would be shorter and handles escaped brackets better. Not a 0.84 API (regex package is old), noted while in the area.
- [x] `hybrid.kuki` — `sort.By(ids, (a, b) => scores[b] < scores[a])` (RRF fusion, descending by score) → `sort.ByKeyDesc(ids, (id) => scores[id])` (new). Same file: the capped build loop below could stay.
- [x] `format.kuki:26,36,49` — `table.AddRow` with pre-truncated/`fmt.Sprintf("%.4f")`-ed cells → `table.AddRowValues` (new) is a partial fit: the distance cell needs `%.4f` precision so it must stay formatted; plain cells (`h.Id`, `h.Type`) could go raw. Low value.
